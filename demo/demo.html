Tackback

Anchored comments for any web page — pin a comment to a block, a phrase, or a region (images, diagrams and other non-text content included). Export as JSON, import it back, or hook into a backend. One <script>, zero runtime dependencies, no backend.

Try it: right-click any text block to comment it; select text first, then right-click, to pin a phrase; right-drag over an image, the inline diagram, or a non-text area to comment a region. Comments appear as 💬 badges; the panel (bottom-right) lists them and exports / imports JSON. The bar at the bottom-left switches the UI display language is not part of Tackback: it drives the options an integrator passes in, so you can see what is customizable and what each one changes — the colour scheme, the reaction set, the language, which panel buttons are shown, and whether a transport is attached (Save vs Send). The bar across the bottom — 🗒 About this document — is a thread about the whole document rather than any place in it: type straight into it, or open it to read. What it is

Tackback attaches durable, anchored comments to a document without changing the document. Each comment remembers where it was placed — a block, a selected phrase, or a region drawn over an image, diagram or other non-text content — and re-finds that spot when the page is re-rendered.

It ships as a headless core plus an optional default panel. The core holds no opinion about the DOM; the panel is one way to drive it. Everything in this page (except the PDF preview at the bottom) runs from a single bundled script with no network calls and no external packages.

The three anchor kinds (v1)

Block

The simplest anchor: a whole element. Right-click this paragraph and the comment pins to it, surviving re-renders as long as the element keeps its identity.

Range (phrase)

Select a few words inside this sentence and right-click — the comment pins to the exact quote using a W3C-style text selector, highlighted without rewriting the DOM. If the text later drifts, the comment is marked orphaned rather than silently re-anchored to the wrong place.

Region (rectangle over non-text content)

Right-drag a rectangle over the inline diagram, the image, or any non-text surface to anchor a comment to that area — no PDF required. The box is stored as a normalized rect, so it follows zoom and scroll, and the rectangle you drew stays visible while you type. The v1 region surface is the DOM-rendered document: an inline <svg>, an <img>, a <figure>, or any element.

Why anchoring is the hard part

A comment is only as useful as its ability to find its way back to what it was about.

Most lightweight comment tools store an offset or an XPath and break the moment the document changes. Tackback stores a resilient descriptor per anchor type and degrades honestly when it can't resolve — the difference between a review tool you trust and one you don't.

PDF page region — post-v1 preview, optional sample

This block is a demo, not a v1 feature. Tackback v1 annotates the DOM-rendered document (the sections above). A region over a raster surface that is not in the DOM — a PDF page or a <canvas> — is post-v1, shipped only as this optional pdf adapter sample. It is shown here to demonstrate that Tackback can annotate a page that contains a PDF; it is not a v1 focus. pdf.js is the consumer's own peer dependency (loaded here from a CDN), so this block — unlike the rest of the page — needs network and falls back to a note when offline.
